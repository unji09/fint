## 1-2. 빌드 시 사용되는 환경 변수

### 빌드타임에 **반드시 주입**해야 하는 변수

| 변수 | 대상 | 주입 위치 | 설명 |
|------|------|-----------|------|
| `NEXT_PUBLIC_API_URL` | Frontend Web | `docker build --build-arg` (Jenkins `Build Frontend Image` 단계) | Next.js는 `NEXT_PUBLIC_*`를 **빌드 시점에 번들에 박음**. 런타임 주입 불가 — 반드시 ARG로 전달 |

```bash
# Web 이미지 빌드 예시
docker build \
  --build-arg NEXT_PUBLIC_API_URL=https://k14a301.p.ssafy.io/api/v1 \
  -t fint-frontend:latest frontend-web
```

### 서비스별 빌드 명령

| 서비스 | 명령 |
|--------|------|
| Backend (JAR) | `./gradlew bootJar -x test --no-daemon` |
| Backend (이미지, Jenkins) | `docker build -f Dockerfile.runtime -t fint-backend:latest .` (사전 빌드 JAR 사용) |
| Backend (이미지, 풀빌드) | `docker build -f Dockerfile ...` (멀티스테이지, Gradle/JDK 불필요) |
| Frontend Web | 위 `--build-arg` 포함 빌드 |
| AI | `docker build -t fint-ai:latest ai` |
| Android | `./gradlew assembleRelease` |

> 그 외 런타임 환경변수(`.env.dev`)는 빌드가 아니라 컨테이너 기동 시(`docker compose --env-file .env.dev`)에 주입된다. 1-4 참조.

## 1-3. 배포 시 특이사항

1. **`NEXT_PUBLIC_API_URL`은 런타임 변경 불가** — 빌드 시점에 번들에 박히므로, 도메인이 바뀌면 Web 이미지를 다시 빌드해야 한다.
2. **SSL 인증서 선발급 필요** — Let's Encrypt `certbot certonly --standalone`을 **Nginx 미실행 상태(80포트 비점유)** 에서 먼저 수행해야 한다. 발급 인증서는 `infra/docker-compose.dev.yml`이 자동 마운트.
3. **Flyway `ddl-auto: validate`** — Spring 기동 시 마이그레이션을 자동 적용하며, 엔티티-스키마 불일치 시 **기동 자체가 실패**한다.
4. **Backend 이미지 두 종류 주의** — Jenkins 배포는 사전 빌드 JAR + `Dockerfile.runtime`(경량), 로컬/수동은 `Dockerfile`(멀티스테이지 풀빌드). 용도를 혼동하지 말 것.
5. **`INTERNAL_SECRET` 미설정 시 Spring ↔ AI 호출 거부** — 양쪽에 동일 값을 넣어야 내부 통신이 동작한다.

### 발급 시 주의

- **SSAFY GMS**: OpenAI를 직접 호출하지 않고 GMS 프록시를 경유한다 — `OPENAI_BASE_URL`을 반드시 GMS 주소로 설정.
- **AWS**: IAM 사용자에 S3(Get/Put/Multipart) + KMS(Encrypt/Decrypt/GenerateDataKey) 권한이 필요하다. 버킷 KMS 키 alias는 `alias/crm-fint-s3-key` 기준.
- **FCM**: `FCM_CREDENTIALS_PATH`가 가리키는 서비스 계정 JSON을 컨테이너에 마운트해야 동작한다. Android는 추후 `google-services.json` 추가 + `frontend-app/app/build.gradle.kts`의 Firebase 의존성 주석 해제가 필요하다(현재 비활성).
- **DART**: 한 키당 일일 호출 한도가 있으므로 운영 시 호출량을 고려한다.
